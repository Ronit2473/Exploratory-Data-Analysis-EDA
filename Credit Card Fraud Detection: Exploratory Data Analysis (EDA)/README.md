# 💳 Credit Card Fraud Detection: Exploratory Data Analysis (EDA)
# 🌟 Project Overview
# This repository contains the Exploratory Data Analysis (EDA) performed on a synthetic financial dataset, aiming to understand the characteristics and patterns of fraudulent credit card transactions.
# The primary goal of this EDA was to identify key features and data distributions that distinguish fraudulent transactions from legitimate ones, which is a critical first step before building an effective machine learning fraud detection model.
# 📚 Data Source
# The data used for this analysis is a synthetic dataset generated by the PaySim simulator. It models mobile money transactions over a 30-day period and is commonly used for fraud detection research.
# Dataset Link: Synthetic Financial Datasets For Fraud Detection
# 📊 Key EDA FindingsThe analysis revealed several crucial insights, particularly concerning the data imbalance and the nature of fraudulent activity:Severe Class Imbalance: The dataset is highly imbalanced, with 99.87% of transactions being non-fraudulent and only 0.13% being fraudulent. This highlights the need for specialized modeling techniques (e.g., using Recall or AUC-ROC as primary metrics).Fraud is Type-Specific: 100% of the fraudulent transactions are concentrated in only two categories:CASH_OUT (50.11% of all fraud cases)TRANSFER (49.89% of all fraud cases)Fraudulent Transaction Signature (The "Zero Balance" Scam):High Amounts: Fraudulent transactions are moderately correlated with higher transaction amounts ($0.44$).Account Drain: In most fraudulent cases, the money transferred or cashed out is equal to the originating account's entire old balance, leaving the new balance at zero. This distinct pattern is a strong indicator of fraud.Balance Volatility vs. Absolute Balance: While the absolute balance of an account (oldbalanceOrg, newbalanceDest) is not a strong predictor of fraud (low correlation), the change in the original account's balance is highly informative.💻 Analysis DetailsThe notebook performed the following steps:Data Loading & Inspection: Loaded the data and checked its structure, data types, and presence of null values (none found).Target Distribution: Visualized the extreme imbalance in the isFraud column.Categorical Analysis: Analyzed the distribution of type (transaction type) and calculated the fraud rate for each type.Correlation Analysis: Generated a heatmap to show relationships between numerical features.Distribution Comparison: Used KDE plots (Kernel Density Estimate) to compare the distributions of features like amount, oldbalanceOrg, and newbalanceOrig between fraudulent and non-fraudulent classes.Feature Engineering (Exploratory): Calculated orig_balance_change and dest_balance_change to analyze balance dynamics related to fraud.
